# LLM Wiki 规范

这是本地个人 LLM Wiki 的唯一页面规则来源。`Wiki/AGENTS.md` 只是此文件的
Vault 副本；不要在应用代码或用户页面中维护另一份模板。

## 权威边界

- 不可变来源保存原始文本、来源类型、来源标识和 SHA-256；来源永不被摘要覆盖。
- SQLite 保存实体、事实、关系、生命周期、证据和页面绑定。
- Markdown 保存用户可读的 Wiki 正文、索引和追加日志。
- FTS、向量和 Kuzu 都是可删除、可重建的读取投影，不得作为事实来源。
- LLM 只能抽取、消歧、综合和规划查询；写入、权限、生命周期、引用校验和删除由确定性代码完成。

## 页面类型

### source

来源信息、不可变摘录、可验证主张、关联实体、引用和来源哈希。不要把模型推断写进原文摘录。

### entity

实体定义、已确认事实、关系、冲突/过期信息、来源和更新记录。没有证据的候选只能显示为待确认。

### concept

定义、核心要点、案例、误区、关系、来源和更新记录。缺少内容的可选段落必须省略。

### synthesis

问题、结论、支持证据、反证与不确定性、影响、来源和更新记录。至少两个独立 evidence 才能称为综合；单一来源必须标记为单来源摘要。

### comparison

比较对象、共同证据、差异、限制、来源和更新记录。不得凭共享关键词制造关系。

### decision

用户明确决定、背景、依据、替代方案、风险、后续检查、来源和未解决问题。模型推断与用户决定必须分开标记。

### report

检查范围、通过项、失败项、证据、后续动作和生成信息。报告不能伪造成功数据。
`Wiki/Companion/Summaries/` 中的助手回答摘要也属于 report，不属于原始 source。
归档或写入成功只证明内容已保存；助手摘要和问答报告不能独立支持其所述事实。

## Frontmatter 契约

每个可维护页面都必须包含 `wiki_id`、`page_type`、`entity_ids`、`fact_ids`、`revision`、`confidence`、`disputed`、`sources`、`updated_at`。`sources` 不得为空；推断页必须包含 `inference: true`。

## 写入生命周期

`source -> entity -> fact/relation -> page -> index/log -> lint`。每一步都绑定 evidence、Vault、内容哈希和生命周期。重复来源按 source hash 幂等；冲突事实并排保留，未解决冲突不能进入确定性答案。

## 失败边界

模型离线时保留来源、浏览、手工编辑和确定性搜索；Kuzu 损坏时回退 SQLite；Markdown 冲突时停止该页面写入并保留快照；lint 失败时页面保持可读但不得宣称已验证。

## 页面生成边界

- renderer 只生成当前页面类型有真实内容的章节；空的可选章节直接省略。这不是每页必须填满的八段模板。
- 不使用通用八段模板，不生成“无”“待补”“经典案例”等占位内容，也不伪造引用或成功状态。
- 单一来源写成 source/entity/concept 或明确标记的单来源摘要；synthesis 和 comparison 需要独立 evidence，decision 需要用户明确决定。
