# v0.1 Validation Commands

Date: 2026-05-02
Executor: Codex

This document is the local validation command set for the v0.1 backend/desktop acceptance gate. It maps existing scripts to the acceptance areas they cover and does not add product scope.

Run commands from `E:\agentproject` unless a command block changes directory.

## Current Acceptance Boundary

The v0.1 validation target is the local runnable core loop:

- backend sidecar contract, smoke chain, and cleanup;
- Electron startup and control-console access;
- Electron-managed sidecar state persistence and active Vault status restore on startup;
- control-console health, model test, Vault, indexing/search, memory proposal, task, Chat SSE tool-event visibility, and diagnostics flows;
- desktop package readiness and Live2D resource presence checks.

Desktop-pet visuals are manual observations, not core gate blockers, unless they prevent opening or using the control console. Current code keeps the compact top bubble fixed and presents long Agent replies through semantic pagination, not a growing text bubble. Structured audit logs are part of the local runnable core loop and should be validated through `/api/diagnostics/export`. Do not count lip sync, voice, multi-character switching, complex motion queues, screen-edge snapping, installer UX, notification polish, or auto-update as v0.1 requirements.

For the current MVP-08 pass, packaging and signed launch validation are intentionally deferred. The core validation focus is real-model Chat behavior, retrieval grounding, SSE tool events, memory proposal visibility, and task/reminder operability in the control console.

## Test Path Convention

`E:\agentproject\.tmp` is the recommended temporary artifact folder for local smoke output. It is not a required user Vault location.

- One-key smoke: `.\scripts\runbook-smoke.ps1` creates `E:\agentproject\.tmp\runbook-smoke-<timestamp>`.
- Manual backend smoke: use `.\scripts\smoke-backend.ps1 -BaseUrl http://127.0.0.1:8765 -SessionToken dev-token -WorkDir E:\agentproject\.tmp\manual-v0.1-smoke`.
- Manual Vault practice: use `E:\agentproject\.tmp\PetMemoryVault`.
- User folder trial: use a writable user directory or an Obsidian Vault copy; back up real notes first.

Do not point `-WorkDir` at a real Vault unless the goal is a controlled trial on a backed-up test Vault.

Failures should be categorized with a stable code such as `not_configured`, `authentication_failed`, `unsupported_model`, `provider_timeout`, or `provider_unreachable`.

## Manual Desktop Trial Checklist

Run after the command gate:

1. Start Electron with `npm run electron:dev`.
2. Confirm the desktop-pet shell appears.
3. Open the control console.
4. Confirm Health succeeds or shows a clear Chinese error.
5. Save model settings and click `试连模型`; success or a categorized Chinese failure must be visible.
6. Initialize a test Vault and trigger indexing.
7. Search Markdown content and confirm success, empty, unindexed, and error states are distinguishable.
8. Create, confirm, and reject memory proposals.
9. Create, complete, and cancel tasks.
10. Send `提醒我明天下午三点测试桌面记忆助手` or `提醒我30分钟后测试桌面记忆助手`; the task event and task list should show reminder time, `北京时间`, and reminder status.
11. Create a near-term reminder, wait until it is due, reload tasks, and confirm backend reminder status becomes `triggered`; in Electron, confirm one system notification is shown for that triggered reminder.
12. Send Chat messages and confirm SSE status, citation, memory proposal, and task events are visible in the Chat panel.
13. Confirm the Core Workflow panel shows model, knowledge/index, Chat tool event, memory proposal, and task/reminder state in one place; use `定位` to jump to the latest linked result/card when available.
14. Export diagnostics and confirm database, Vault, index jobs, and task state are visible.
15. Close Electron and run `.\scripts\check-trial-processes.ps1`.

## Startup State Restore

The Electron-managed backend sidecar should persist local backend state in the Electron user-data directory by default. Current code sets a stable managed data directory in `apps/desktop/electron/main.cjs` and injects it as `AGENT_PET_DATA_DIR` unless an explicit `AGENT_PET_DATA_DIR` or `AGENT_PET_SQLITE_PATH` override is already present.

Validation focus:

- `apps/desktop/electron/main.cjs` should keep `app.getPath("userData")` and `backend-state` as the managed sidecar state location.
- `npm run package:check` should report that Electron main gives the managed sidecar a persistent data directory.
- `apps/backend/tests/test_api_wiring_mvp.py::test_vault_status_recovers_persisted_active_vault_after_restart` should remain covered by backend pytest.
- After a manual Electron restart, the control console should show the previously active Vault through `/api/vaults/status` without forcing the user to reinitialize the knowledge-base path.

Explicit environment overrides remain valid for isolated tests and development:

```powershell
$env:AGENT_PET_DATA_DIR = "E:\agentproject\.tmp\manual-sidecar-state"
$env:AGENT_PET_SQLITE_PATH = "E:\agentproject\.tmp\manual-sidecar-state\state.sqlite3"
```

Do not set both during normal desktop-pet trial unless the goal is to test override precedence.

## Desktop-Pet Reply Bubble

The current compact-bubble implementation keeps full Agent reply text in React state but displays long replies as semantic pages generated by `apps/desktop/src/services/petBubblePagination.ts`. The visible `.pet-agent-bubble-text` region is intentionally clipped inside the fixed 214x58 top bubble; pagination is the current code behavior for avoiding both truncation and bubble growth.

Validation command:

```powershell
Push-Location apps\desktop
npm run pet:bubble:check
Pop-Location
```

Manual observation:

- Double-clicking the pet model should reveal the input dock.
- Sending from the pet input should hide the input dock.
- Status/tool/reminder events may show compact transition text before the reply starts.
- Long reply content should progress through compact semantic pages without enlarging the bubble or overwriting the started answer with later status events.

## Current v0.1 Interpretation

- Passing the required gate means backend API contracts, persistence, memory proposals, retrieval, task service, isolated backend smoke, Electron migration, packaging readiness, and core console trial path are locally verified.
- `docs\mvp-acceptance-coverage.md` remains the source of accepted gaps and partial coverage.
- Current desktop startup restores the active Vault only when the same persisted backend state is reused; explicit state-path overrides intentionally create isolated state.
- Current desktop-pet long replies use compact semantic pagination rather than a scrollable/growing bubble.
- v0.1 covers common Chinese reminder-time parsing, Beijing timezone display/aliases, backend reminder `triggered` state, Electron system notification delivery for triggered reminders, and structured audit/application logs. It does not promote full natural-language date parsing, full tray product polish, signed auto-update, lip sync, complex Live2D action orchestration, or multi-character support.
